# Огляд Wishlist — 9 листопада 2026

## Що є зараз

Невеликий застосунок без збірки: інтерфейс і логіка в `index.html`, серверна функція Vercel — `api/product.js`, авторизація та дані — Supabase. Git remote вказує на `pindel-kateryna/wishlist`. Цього достатньо для особистого вішліста; переписувати все на інший фреймворк зараз не потрібно.

Переглянуто всі наявні вихідні файли. Доступу до конфігурації живих Supabase/Vercel і SQL функцій у цьому репозиторії немає, тому їхня коректність та безпека не підтверджені.

## Що виправлено локально

- Фото можна вибрати з галереї незалежно від результату імпорту та навіть без посилання. Є попередній перегляд, видалення й заміна фото.
- Фото стискаються у JPEG з максимальною стороною 1200 px. Вхідний файл — до 20 MB; збережене зображення — до 350 000 символів data URL. Непідтримувані браузером формати отримують зрозуміле повідомлення. Для HEIC підтримка залежить від браузера; JPEG/PNG — надійніші варіанти.
- Додано редагування існуючих товарів: назва, ціна, посилання, список, нотатка і фото.
- Імпорт читає структуровані дані Product/JSON-LD, Open Graph та Twitter, незалежно від порядку атрибутів. Відносні фото визначаються щодо кінцевої адреси після перенаправлень.
- Додано окремий адаптер для сучасних посилань dm.de та applink.
- Збій магазину не стирає фото чи введені дані. Відповідь від старої закритої форми не потрапляє в нову. Повторне збереження блокується під час запиту.
- Помилки завантаження списків, видалення товару, зміни статусу та скасування бронювання більше не ігноруються.
- Сервер перевіряє адресу на кожному перенаправленні, відхиляє приватні IPv4 та IPv6-адреси й фіксує перевірену IPv4 для з’єднання. Є обмеження обсягу відповіді й часу HTTP-запитів, підтримка gzip/br. Домени лише з IPv6 поки не підтримуються.

## Два надані приклади

**dm:** початкове посилання перенаправляє на сторінку, чий HTML містить загальну оболонку без даних товару. Публічний скрипт dm вказує на product API. Новий адаптер реально отримав назву `MAYBELLINE NEW YORK Primer Serum Grippy, 30 ml`, фото й ціну `11,95 €`. Це результат перевірки на дату огляду, а не гарантія незмінної ціни чи API. Адаптер обмежено точними доменами dm.de та форматом шляху товару; якщо API зміниться, залишається стандартний імпорт і ручне введення.

**Douglas:** запити з середовища перевірки, зокрема з початковим User-Agent застосунку, повертали HTTP 400 із повідомленням про завеликі заголовки. Причину на стороні магазину/мережевого шляху не встановлено; не можна стверджувати, що це саме захист від ботів. Імпорт цього конкретного посилання не підтверджений. Новий інтерфейс дозволяє зберегти товар вручну з власним фото.

## Що покращити далі, за пріоритетом

1. **Перевірити права Supabase.** У репозиторії немає SQL схеми, RLS-політик та реалізацій `get_shared_list`, `reserve_item`, `cancel_reservation`. Потрібно перевірити, що сторонній користувач не може читати приватні списки чи змінювати чужі товари, а двоє гостей не можуть одночасно забронювати той самий подарунок. Це перевірка невідомого стану, а не висновок, що витік уже є. Publishable key у браузері очікуваний; захист має забезпечуватися правилами бази. Твердження інтерфейсу, що ім’я гостя не бачить власник, також залежить від SQL і наразі не перевірене.
2. **Перенести власні фото в Supabase Storage.** Поточний варіант зберігає стиснений data URL у наявному `image_url`, тому не потребує створення bucket. Він припускає, що поле допускає текст такого розміру; схема в репозиторії відсутня. Фото завантажуються разом з усіма рядками товарів, що обтяжує великий список. Для подальшого розвитку потрібні Storage, політики доступу та видалення невикористаних файлів. [Документація завантаження](https://supabase.com/docs/guides/storage/uploads/standard-uploads), [правила доступу](https://supabase.com/docs/guides/storage/security/access-control).
3. **Зберігати суму й валюту окремо.** Зараз ціна — довільний текст, а підсумок завжди позначено євро. `1.299,90 €` розбирається неправильно; USD та EUR змішуються. Потрібні числове поле, окрема валюта та підсумки для кожної валюти.
4. **Покращити щоденне користування.** Додати пошук, сортування, пріоритет бажання, редагування назв списків і кошик для відновлення видаленого. Український інтерфейс і зрозумілі підписи вкладок замість самих емодзі зроблять застосунок доступнішим. Модальним формам потрібні керування фокусом і попередження про втрату незбережених змін.
5. **Зробити розвиток передбачуваним.** Винести CSS і клієнтський JS з HTML, зафіксувати версію Supabase SDK, додати SQL-міграції, перевірки в GitHub та окремі Vercel Preview перед production. Після доступу до налаштувань — перевірити обмеження API, логи, резервне копіювання й поведінку після завершення сесії.

## Перевірка та межі

- `node --test tests/*.test.js`: перевіряє метадані, JSON-LD, dm, авторизацію API, перенаправлення, стиснені відповіді та блокування приватних адрес.
- Синтаксис усіх inline JavaScript та `git diff --check` перевірено.
- В ізольованому браузерному демо з підставленим клієнтом Supabase перевірено вибір локального зображення, стиснення/прев’ю, збереження після невдалого імпорту та повторне відкриття фото в редакторі. Це не перевірка запису в живу базу.
- Реальний запит нового адаптера dm успішний. Douglas залишається непідтвердженим.
- Зміни локальні: push у GitHub, публікація на Vercel і зміни Supabase не виконувалися.
